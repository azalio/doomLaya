## Запустить игру

Перед запуском установите исправление ViZDoom для перехода на MAP03:

```bash
.venv/bin/python scripts/install_vizdoom_sector_fix.py
.venv/bin/python -m unittest tests.test_map2.Map02Test.test_map02_to_map03_preserves_large_sector_geometry
```

Для сборки на macOS нужны `cmake`, `boost`, `sdl2`, `openal-soft`;
на Ubuntu — `cmake`, `libboost-all-dev`, `libsdl2-dev`, `libopenal-dev`.
Установщик соберёт ViZDoom `1.3.1.post1` из закреплённой ревизии;
после этого запустите сервер и игру в разных терминалах.

В первом терминале:

```bash
.venv/bin/python serve_doom_laya.py \
  --checkpoint checkpoints/laya-doom-map02/laya-map2-explicit-v2 \
  --item-head-checkpoint checkpoints/laya-doom-map02/laya-map2-goal-invariant-items-v1 \
  --head-checkpoint movement=checkpoints/laya-doom-map02/laya-map2-explicit-movement-v1 \
  --head-checkpoint command=checkpoints/laya-doom-map02/laya-map2-root-goals-v1 \
  --head-checkpoint switch=checkpoints/laya-doom-map02/laya-map2-stable-goals-v1 \
  --device auto --port 8001
```

Во втором терминале:

```bash
.venv/bin/python agent.py --model doom-adapted \
  --endpoint http://127.0.0.1:8001/predict --decision-format committed \
  --question-schedule conditional --interval 0.5 --explicit-actions \
  --explicit-movement --movement-facts --refresh-attack-target --weapon-sensor --map-weapons --reachable-items \
  --mechanism-facts --combat-during-navigation --pickup-recent-targets \
  --inventory-events --ammo-events --mask-unreachable-items \
  --map MAP02 --skill 3 --seed 54 --seconds 1800 \
  --record auto --show --stop-after-level --tag map02
```

Игра напечатает каталог `RUN`. В нём сохраняются `video.mp4`, телеметрия,
запросы к модели, ответы и копия использованных исходников.
`--stop-after-level` завершает запись после трёх секунд игры на MAP03.
Для запуска без окна уберите `--show`. Сервер выбирает самый вероятный ответ
модели (`argmax`), без случайной выборки. Включены точное наблюдение оружия
и координаты оружия из карты; подробнее — ниже.

```bash
.venv/bin/python -m tools.check_authority runs/<каталог-RUN>
.venv/bin/python -m tools.verify_run runs/<каталог-RUN>
```

Первая проверка сопоставляет кнопки с принятыми ответами модели.
Вторая проверяет завершение MAP02, старт MAP03, запись видео, скорость игры
и задержку перехода на более мощный дробовик (не более 1,5 с).
В отчёте отдельно показаны целостность эксперимента, прохождение и задержки движения.

## Как принимаются решения

Laya отдельно выбирает действие, цель, оружие и движение в бою. Например,
для атаки нужны ответы о действии `attack`, конкретном враге, направлении
движения и оружии. Так варианты атаки разных врагов не делят вероятность
выбора самого действия между собой.

В текущей конфигурации включён `--explicit-actions`: модель каждый
раз выбирает действие и его цель заново. Текущая цель остаётся во входных данных,
но ответ `continue` для действия отсутствует. На прежних весах
`laya-map2-route-contrasts-v3` проверены 40 сохранённых состояний: повторный выбор лифта к уже взятому ключу сократился с 13 до 3
случаев из 20, а атаки дальних врагов — с 15 до 5 из 20. На другом наборе
ошибок число совпадений с офлайн-разметкой выросло с 19 до 22 из 48.
Игровой запуск без дообучения остановлен на 433,657 с: восемь смертей,
105 убийств, ни одного ключа. Это незавершённый диагностический прогон:
`runs/20260925_211835_336635_map02-explicit54`. Задержка решения —
733,7 мс по медиане. Вместе с форматом ответа изменилось расписание
запросов с `conditional` на `parallel`, поэтому результат не выделяет
влияние одного лишь `--explicit-actions`.

Без `--explicit-actions` команда `continue` сохраняет текущую цель, а одноимённый ответ о движении —
текущее направление. При `--refresh-attack-target` продолжение боя запрашивает
новый выбор врага у Laya: подошедший противник может изменить её выбор.
Цель предмета или переключателя при продолжении сохраняется. Модель получает текущую команду, результат её исполнения
и категорию расстояния до ближайшего врага вместе с точными значениями.
При новом действии используются ответы о новой цели. Продолжение требует
нового ответа модели; срок действия команды остаётся равным двум секундам.

В режиме `conditional` первый запрос выбирает действие и оружие. Второй
запрашивает только параметры выбранного действия: например, врага и движение
для новой атаки. Без `--combat-during-pickup` продолжение пути к предмету
не требует второго запроса. С этим флагом второй запрос снова выбирает
врага для стрельбы либо `hold`. При включённом `--refresh-attack-target`
продолжение боя запрашивает врага и движение.
В задержку решения входят оба запроса; токены и стоимость складываются.
На 16 сохранённых состояниях итоговые команды совпали с одновременным запросом
всех вопросов, а медианная задержка снизилась с 618 до 275 мс. Это проверка
способа вызова модели, а не доказательство прохождения уровня.

Контроллер соединяет ответы в команду и исполняет её: строит путь, целится,
нажимает USE и ждёт подъёма выбранного лифта. Он не назначает приоритет боя
или полезность предмета. При столкновении в бою исполнитель делает короткий
боковой шаг, сохраняя выбранную цель и прицел; в видео это отмечено как `recover`.
Ошибка API не включает запасную стратегию.

В режиме `--combat-during-pickup` Laya отдельно разрешает огонь во время сбора
предмета. Ответ `hold` запрещает стрельбу; ID врага разрешает стрелять только
по нему. Исполнитель следует маршруту к выбранному предмету и поворачивает
прицел к выбранному врагу. Оба ответа и обе цели сохраняются для аудита.
Флаг `--pickup-recent-targets` добавляет в этот вопрос врагов, виденных
за последние две секунды. Модель может выбрать такого врага для прицеливания;
огонь разрешён только после его появления в кадре. Пока выбранный враг
остаётся в краткой памяти, исполнитель сохраняет прицел. При повторной офлайн-обработке 28 сохранённых запросов с новым флагом
Laya выбрала ближайшую недавно виденную угрозу в 26 случаях.
Это проверка доступности цели и выбора модели, а не доказательство прохождения.
На видео составная команда обозначена как `pickup+fire`. Веса для этого режима
в этапах 1–11 отдельно не дообучались. Этап 12 добавляет разметку этого вопроса.

Вход содержит здоровье, инвентарь, видимых врагов и недавние наблюдения о них
за последние две секунды, запомненные предметы, ключи и результаты исполнения
команд. Стрелять разрешено только по наблюдаемой в текущем кадре цели.
Из WAD доступны геометрия, выход, переключатели, телепорты и координаты ключей.
Это расширение относительно опубликованного сравнения MAP01: его цифры относятся
к сохранённым там исходникам. Эксперимент не оценивает игру только по изображению.

На MAP02 красный и синий ключи открывают проходы к жёлтому, который нужен
для выхода. Добавлены команда переключателя и фазы лифта; навигация учитывает
радиус игрока, ключи, движущийся пол, спуски и телепорты. Недостижимая цель исключается после
ошибки поиска пути. Список обновляется при смене доступной области, высоты пола, ключей или
дверей, управляемых переключателем. Открытие обычной двери его не очищает:
поиск пути уже считает такой проход доступным.

## Повторить обучение

Это обучение по размеченным примерам, а не обучение с подкреплением.
Тринадцать этапов ниже выполняются последовательно. В первых двух обучаются голова
решений и последние три слоя энкодера, в этапах 3–7 — только голова,
в восьмом — голова и последний слой энкодера, в этапах 9–12 — только голова,
в тринадцатом — голова и два последних слоя энкодера.
Исходный v3 сохраняется.
Команды его загрузки — в [README](../README.md#запуск-адаптации-v3).

Готовые JSON включены в репозиторий; исходные игровые записи для повторения
обучения не нужны. Первый набор — `training/map2-factorized-v2`:
1904 обучающих и 461 проверочный вопрос. Второй — `training/map2-corrections-v2`:
1310 и 400 вопросов соответственно. Хеши и источники зафиксированы в `manifest.json`
этих каталогов и в [манифесте исходной разметки](../training/map2-v5/manifest.json).

Этапы 1 и 2:

```bash
.venv/bin/python training/finetune.py \
  --base checkpoints/laya-doom-v3 --data training/map2-factorized-v2 \
  --epochs 4 --lr 0.0003 --encoder-last 3 --device auto \
  --max-len 1024 --head-max-len 384 \
  --output checkpoints/laya-map2-factorized-repro

.venv/bin/python training/finetune.py \
  --base checkpoints/laya-map2-factorized-repro \
  --data training/map2-corrections-v2 \
  --epochs 3 --lr 0.0001 --encoder-last 3 --device auto \
  --max-len 768 --head-max-len 384 \
  --output checkpoints/laya-map2-corrected-repro
```

Эти два этапа дают промежуточные веса. Для их отдельной проверки укажите серверу
`--checkpoint checkpoints/laya-map2-corrected-repro`, а игре —
`--decision-format factorized`. При этом уберите `--explicit-actions`
и `--refresh-attack-target`: эти флаги требуют режима `committed`.
Для актуального режима `committed` выполните следующие этапы ниже.
На CUDA замените `--device auto` на `--device cuda`.
Скрипт откажется перезаписывать существующий каталог.

Данные первого этапа включают офлайн-разметку полного прохождения с монстрами,
проверок механизмов без монстров, искусственных состояний и часть прежних примеров
MAP01. Во втором этапе исправлены решения из неудачного прогона самой Laya:
стрельба по дальним врагам при доступном дробовике, атака без патронов и неподвижность
в бою. Правила разметки не подключаются к игровому агенту.

Seed 48, 49 и 54 использованы для обучения или отладки; их не следует считать
независимой проверкой. Разделение исправленных примеров
по эпизодам не делает итог независимой проверкой обобщения на новые seed или карты.
Веса выбираются по точности ответов на проверочных вопросах; факт прохождения
устанавливается отдельным игровым запуском.

## Этап 3: обучить голову решений

После двух этапов выше можно обучить голову на объединённом наборе
`training/map2-combined-v1`: 3090 обучающих и 810 проверочных вопросов.
В него входят полный маршрут и исправленные решения двух неудачных запусков.
Энкодер на этом этапе заморожен. Его результаты кешируются в оперативной памяти;
перед обучением скрипт проверяет совпадение обычного и кешированного вычислений.

```bash
.venv/bin/python training/finetune.py \
  --base checkpoints/laya-map2-corrected-repro \
  --data training/map2-combined-v1 --epochs 12 --lr 0.0001 \
  --encoder-last 0 --cache-encoder --device auto \
  --max-len 768 --head-max-len 384 \
  --output checkpoints/laya-map2-combined-repro
```

Кеш требует несколько гигабайт оперативной памяти. Если памяти не хватает,
уберите `--cache-encoder`: обучение выполняет ту же операцию, но каждый раз
заново вычисляет выход энкодера. Исходные веса сохраняются.

## Этап 4: обучить продолжение текущей цели

Четвёртый этап использует `training/map2-committed-v2`: 2511 обучающих
и 744 проверочных вопроса. Разметка полных маршрутов и ошибок Laya использует
одну офлайн-стратегию. Вопросы о новой цели обучаются в состояниях, где нужно
выбрать её заново. Для сохранения прежней цели модель выбирает `continue`.

```bash
.venv/bin/python training/finetune.py \
  --base checkpoints/laya-map2-combined-repro \
  --data training/map2-committed-v2 --epochs 6 --lr 0.0001 \
  --encoder-last 0 --cache-encoder --command-weight 3 --item-weight 2 \
  --device auto --max-len 640 --head-max-len 384 \
  --output checkpoints/laya-map2-committed-repro
```

При выборе checkpoint точность действия имеет вес 3, нового предмета — 2,
остальных вопросов — 1. Эти веса используются для выбора эпохи, а не
для управления игрой. Для своих весов замените путь сервера на
`checkpoints/laya-map2-committed-repro` и сохраните `--decision-format committed`.

## Этап 5: дообучить на последних ошибках

Набор `training/map2-committed-replay-v1` содержит 3087 обучающих
и 778 проверочных вопросов. В него добавлены решения из прогонов с условными
запросами: атаки дальних врагов, расход боезапаса и повтор команды перед дверью.
Факты о двери и результате исполнения поставлены в начало наблюдения.
Разметка выполняется офлайн; в игровом агенте учителя нет.

```bash
.venv/bin/python training/finetune.py \
  --base checkpoints/laya-map2-committed-repro \
  --data training/map2-committed-replay-v1 --epochs 12 --lr 0.0001 \
  --encoder-last 0 --cache-encoder --command-weight 3 --item-weight 2 \
  --device auto --max-len 640 --head-max-len 384 \
  --output checkpoints/laya-map2-committed-replay-repro
```

Для проверки воспроизведённых весов замените каталог в команде сервера на
`checkpoints/laya-map2-committed-replay-repro`.
Выбор максимальной вероятности остаётся режимом по умолчанию.
Опции сервера `--choice-temperature .7 --sampling-seed 49` включают
выбор из распределения Laya. Параметр `--sample-questions command item switch`
ограничивает его действием, предметом и переключателем. Враг, оружие и движение
выбираются по максимуму вероятности. Без `--sample-questions` выборка применяется
ко всем вопросам; без `--choice-temperature` все ответы выбираются по максимуму.
Декодер не использует игровое состояние и не меняет веса.

## Различать дробовик и двустволку

ViZDoom сообщает обоим дробовикам слот 3. Поэтому одного `SELECTED_WEAPON`
недостаточно, чтобы проверить, какое оружие выбрала модель. Флаг `--weapon-sensor`
подключает датчик из `assets/weapon_sensor.pk3`: он читает тип активного оружия
и владение каждым типом через ACS. Он не выдаёт предметы и не меняет здоровье,
монстров, геометрию или действия игрока. Исполнитель переключает оружие кнопками.
Чтение типа описано в [CheckWeapon](https://zdoom.org/wiki/CheckWeapon),
передача значений — в [USER-переменных ViZDoom](https://vizdoom.farama.org/api/python/enums/).

При `--map-weapons` Laya получает координаты оружия из WAD, как ранее получала
координаты ключей. Учитываются сложность и режим single-player; оружие только
для мультиплеера исключается. На MAP02 это два обычных дробовика и двустволка.
Это расширяет наблюдение модели, поэтому такие прогоны нужно сравнивать
при одинаковом наборе флагов.

Для проверки механики используются отдельные тесты с выданным оружием:

```bash
.venv/bin/python -m unittest tests.test_weapon_sensor
```

Эти тесты проверяют переключение и расход патронов. Они не считаются
прохождением уровня. Проверка прохождения отклоняет прогоны с `--give`.

## Проверить задержку решений отдельно от модели

Флаг `--inventory-events` запрашивает новое решение после получения оружия
или ключа, а также после смены эпизода. Он не переключает оружие и не выбирает
цель. Если запрос уже выполняется, новый ждёт его завершения. Расход патронов
и урон сами по себе не запускают дополнительные запросы.

Дополнительный флаг `--ammo-events` учитывает, достаточно ли патронов для
выстрела из каждого имеющегося оружия. Например, получение первого патрона

Ранний запрос возникает и когда патронов становится недостаточно для одного
выстрела. Флаг требует `--inventory-events`;
остальные изменения числа патронов не меняют расписание. Это только повод
запросить модель — оружие выбирается из её ответа. Набор из 86 тестов прошёл:
`runs/map02-navigation-ammo-tests.log`.

огня. Без выстрела смена занимает 16 тиков; после начала выстрела — от 23 до
34 тиков в пяти проверенных фазах. Повтор выбора каждые 12 тиков дал ту же
задержку, что одно нажатие. Изменять повторные нажатия по этому результату
оснований нет. В тесте выданы оружие и патроны, монстры отключены; это не
