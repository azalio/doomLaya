Laya прошла MAP03 и сыграла три секунды на MAP04: seed 54, skill 3.
Выход — на 819,914 с, после четырёх смертей. Запись целиком занимает
822,943 с; это один успешный прогон, устойчивость на других seed не проверена.

[Полное видео с телеметрией](https://github.com/azalio/doomLaya/releases/download/v0.3.0/laya-map03.mp4).
Локальная запись: `runs/20260927_113829_722635_map03-item-category54/video.mp4`.
[Проверка и состав весов](../reports/map03-success.json).

Аудит действий модели и полноты записи пройден: 28 803 кадра, 1595
принятых решений. Прохождение подтверждено (`level_completed=true`),
но общая проверка качества не пройдена (`passed=false`): максимальная
неподвижность — 141,83 с, время без нового района — 159,29 с.
Контроллер исполнял решения модели; во время игры веса не менялись.

Ниже — команды для запуска того же комплекта. MAP01 и MAP02 с этими
головами повторно не проверялись; опубликованная v0.2.0 остаётся отдельной
конфигурацией.

Опубликованный комплект — [laya-doom-map03](https://huggingface.co/azalio/laya-doom-map03/tree/v0.3.0).
Код и записи — в [релизе v0.3.0](https://github.com/azalio/doomLaya/releases/tag/v0.3.0).
Для установки окружения используйте [README](../README.md#установка), включая
`requirements-model.txt` и исправленный ViZDoom `1.3.1.post1`.

Из корня doomLaya скачайте веса и проверьте контрольные суммы:

```bash
.venv/bin/hf download azalio/laya-doom-map03 --revision v0.3.0 \
  --local-dir checkpoints/laya-doom-map03
(cd checkpoints/laya-doom-map03 && shasum -a 256 -c SHA256SUMS)
```

В первом терминале запустите сервер. Если порт 8002 занят прежним сервером,
остановите его через Ctrl+C в его терминале.

```bash
cd "$(git rev-parse --show-toplevel)"
caffeinate -i .venv/bin/python serve_doom_laya.py \
  --checkpoint checkpoints/laya-doom-map03/laya-map2-explicit-v2 \
  --item-head-checkpoint checkpoints/laya-doom-map03/laya-map3-item-category-v1 --item-category-facts \
  --command-without-goal --enemy-without-goal --movement-compact-facts --enemy-rank-facts --weapon-compact-facts \
  --head-checkpoint movement=checkpoints/laya-doom-map03/laya-map3-compact-movement-v1 \
  --head-checkpoint command=checkpoints/laya-doom-map03/laya-map3-combat-priority-v1 \
  --head-checkpoint look_gate=checkpoints/laya-doom-map03/laya-map3-look-floor-v2 \
  --head-checkpoint switch=checkpoints/laya-doom-map03/laya-map3-switch-route-v1 \
  --head-checkpoint enemy=checkpoints/laya-doom-map03/laya-map3-ranked-enemy-v1 \
  --head-checkpoint weapon=checkpoints/laya-doom-map03/laya-map3-compact-weapon-v1 \
  --device mps --port 8002
```

Сервер выбирает ответ с максимальной вероятностью. После его запуска
во втором терминале запустите игру с записью:

```bash
cd "$(git rev-parse --show-toplevel)"
caffeinate -i .venv/bin/python agent.py --model doom-adapted \
  --endpoint http://127.0.0.1:8002/predict --decision-format committed \
  --question-schedule conditional --interval 0.5 --minimum-decision-delay-ticks 16 \
  --explicit-actions \
  --explicit-movement --movement-facts --movement-obstacle-facts --refresh-attack-target \
  --enemy-visibility-facts --enemy-commitment-facts --enemy-sequences \
  --look-gate --floor-hazard-facts --attack-turn-rate 9 \
  --weapon-sensor --map-weapons --reachable-items --mechanism-facts \
  --combat-during-navigation --pickup-recent-targets \
  --inventory-events --ammo-events --mask-unreachable-items \
  --map MAP03 --skill 3 --seed 54 --seconds 1200 \
  --record auto --stop-after-level --tag map03-item-category54
```

`caffeinate` не даёт macOS уснуть во время игры. На Linux уберите его из обеих
команд и замените серверный `--device mps` на `--device auto` (CUDA или CPU).
Опубликованный прогон выполнен на MPS; другие устройства отдельно не проверены.
Для видимого окна добавьте `--show`. Игра напечатает путь `RUN`: в этом каталоге
будут `video.mp4`, телеметрия, запросы к Laya, ответы и копия исходников.
Лимит — 20 минут; при прохождении запись закончится после трёх секунд MAP04.

Проверьте завершившийся прогон, подставив напечатанный путь:

```bash
.venv/bin/python -m tools.check_authority runs/<каталог-RUN>
.venv/bin/python -m tools.verify_run runs/<каталог-RUN>
```

Проверка прохождения требует выхода с MAP03 живым игроком и не менее 105 кадров
игры на MAP04. Отдельно проверяются соответствие кнопок ответам модели,
полнота видео, скорость игры и задержки движения.

## Локальные данные разработки

В исходной рабочей директории веса каждого этапа лежат прямо в `checkpoints/`,
а Python модели — в `../../laya/.venv/bin/python`. Поэтому исторические команды
обучения ниже используют эти пути. В отдельном clone используйте Python
из `.venv` и пути скачанных checkpoint. Промежуточные веса создаются командами
обучения; на Hugging Face опубликован итоговый комплект.

Замороженные выборки включены в Git. Для повторения обучения используйте
готовые `train.json` и `validation.json`: сборщики из старых `runs/` описывают
происхождение данных, но требуют локальных записей разработки.
Проверить сохранённую выборку можно, например, так:

```bash
.venv/bin/python training/finetune.py --data training/map3-item-category-v4 --validate-only
```

Далее сохранён журнал разработки. Неудачные и прерванные попытки относятся
к прежним конфигурациям; итоговый результат указан в начале документа.

с красного ключа: менять управление лифтом для этого не потребовалось.

Для последнего участка в наблюдение добавлен факт из геометрии WAD:

## Опасный пол после жёлтого ключа

В конце попытки с очередью учитель стоял в точке около `(2607, 298)`
и терял по 5 HP каждые 32 тика. В WAD эта точка относится к сектору 163:
покрытие `NUKAGE1`, тип сектора 7. Такой тип наносит периодический урон,
что соответствует [исходникам Doom](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/p_spec.c#L963-L968).

Проверка без монстров с изменённой точкой старта подтвердила причину.
За 160 тиков неподвижный игрок потерял ещё 20 HP и закончил с 75 HP.
Игрок, сделавший 30 тиков движения вперёд, вышел с покрытия и сохранил 95 HP.

учитываемого окна. Артефакт — `runs/map03-floor-damage-fixture.json`.

Факт не устанавливает источник каждого попадания: на опасном полу тоже
могут атаковать враги. Все варианты действий остаются доступны модели.

Для обучения подготовлена `training/map3-look-floor-v1`: 1827 учебных

пола — обычный выбор действия вместо осмотра. Это синтетическая проверка
наблюдений, не измерение выживания. Первая попытка обучения остановилась
при сохранении первой эпохи: на диске не хватило места. Её каталог

## Выбор очереди целей

Флаг `--enemy-sequences` позволяет Laya выбрать одну цель или несколько
в заданном порядке. Для одного известного врага доступен один вариант,
для двух — четыре, для трёх — 15: одиночные цели, пары и все шесть полных
порядков. Список известен модели до выбора. Исполнитель переходит к
следующему участнику выбранной очереди, когда предыдущий исчезает из
наблюдений; он не добавляет врагов и не меняет порядок. Новое решение
модели заменяет очередь, истечение срока команды останавливает её.

Флаг требует `--explicit-actions --refresh-attack-target` и обученную голову
с меткой формата `enemy-sequence-v1`. Без флага сохраняется прежний выбор
одной цели. Оружие и движение по-прежнему выбирает модель.

В диагностике повторены тики 8717–8793 прежнего прогона. Кнопки движения
взяты из записи, изменены только прицеливание и огонь. Старый выбор одной
цели привёл к смерти после двух убийств. Заданный вручную порядок дал три
убийства и 3 HP; новый исполнитель точно воспроизвёл этот результат.

## Отдельные оценки целей

Подготовлен ещё один формат входа головы целей: `enemy-ranking-v1`.

остаются доступны. Вероятности перед этим расчётом не округляются до четырёх

примеры с обратным порядком показа вариантов и не использовалась для обучения.
Новая функция потерь обучает весь порядок; энкодер остаётся замороженным.
